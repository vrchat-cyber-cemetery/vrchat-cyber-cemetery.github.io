# 测试、验收与发布计划

更新：2026-10-03。客户端测试待执行；已通过30项离线协议／映射／定位码模型检查，见 [validation](validation/README.md)，不能冒充Unity或性能通过。

## 1. 测试层次

| 层次 | 验证什么 | 不能替代什么 |
| --- | --- | --- |
| 离线构建／Schema | 状态、字段、原子包长度／版本、BC1块、图集映射、额度事件与清理清单。 | Udon实际调用、下载字节保真、GPU内存和节流。 |
| Unity 编辑器测试 | 编辑器生成器、配置引用、布局唯一性、确定性产物、可恢复依赖。 | 实际客户端里的协议与缓存行为。 |
| ClientSim | 移动、交互、UI、文本边界、变量和本地状态。 | 真实远端访客、PCVR 舒适性、网络允许列表及客户端限额。 |
| Windows 桌面客户端 | 真实下载、版本更新、键鼠、多客户端与资源生命周期。 | 头显中的双目阅读、手柄输入和 VR 帧时间。 |
| PCVR 实机 | 字体可读性、身高／坐姿、控制器、性能、眩晕和长时体验。 | 大规模在线人数保证或所有访客设备表现。 |
| 静态网页／GitHub | 无账号阅读、分享、投稿、审核、额度、部署和撤下。 | VRChat世界实测。 |

真实多人至少两台独立会话／账号；同机双客户端用于快速检查但需记录其额外资源竞争，不作为唯一性能依据。

## 2. 数据集与故障集

- 小样本：九类对象、无玩家、三玩家、无图、满 7 张图、中文／英文／特殊字符、长标题、长故事、日期区间、代他人和非 VRChat 人物。
- 规模档：100、1,024、4,096 条；满档覆盖所有合法墓位和所有图片槽。共享同一张图片的去重样例不能替代不同内容的满容量预算测试。
- 非法样本：第四名玩家、第八张逻辑图、重复 ID／墓位、未知类型、坏 JSON、嵌套类型错误、超长文本、坏图、越界 UV／资源索引、未知协议／布局。
- 状态样本：五种状态、普通修订待审、争议先隐藏、撤下后恢复、共享图片中一处被撤下、旧合图残留。
- 故障集：404、429、断网、慢响应、乱序、同地址旧包、截断／超长／错误头、错误BC1长度、部分站点失败、迟到回调、休眠恢复和快速切换。
- 治理集：重复领取、同一评审多评论、自审、利益冲突、两条并发消费、奖励已消费后撤销、账号改名／换绑、镜像恢复、独立 Fork 导入。
- 分享集：未登录阅读、JavaScript 禁用、未知 ID、分享后撤下、外部预览抓取、未授权代建、无评审任务与容量已满。

所有测试人物和账号数据采用合成内容或明确授权的测试数据，禁止用真实隐私材料测试泄露清理。

## 3. 原型预算与性能目标

以下是**建议起始预算**，M1／M6 用指定参考设备复核后冻结；不是 VRChat 官方保证，也不是当前已达指标。

| 项目 | 原型起点 | 测量／超标处理 |
| --- | --- | --- |
| 预留容量 | 64×64＝4,096 墓位 | 完整配置构建、逐区可达；不以减少墓位隐瞒超标。 |
| 活动显示外壳 | 最多 128 | 四区交界和传送复活测试；先改善视线／分区，再评估预算变化。 |
| 解析数据缓存 | 3 个分区，根目录独立 | 退出区域逐步淘汰；不可累计全部正文。 |
| 文本产物 | 根≤64KiB，区概要≤128KiB，组包JSON≤128KiB | UTF-8实际字节检查；故事进入组包，超限拒绝，不运行时截断。 |
| 世界图文包 | 512包，每包≤2,228,256字节 | 原始BC1数据正好2MiB；无图包像素为0，不比较PNG压缩平均值作为世界容量依据。 |
| 网站衍生物 | 每组网页图集≤1MiB，单HTML页≤16KiB | 网站独立预算；超过限制不静默降低到不可读。 |
| 图片缓存 | 最多2缓存＋1暂存图集，纹理块6MiB，预算8MiB | Apply后释放CPU纹理副本；CPU工作集目标≤16MiB，SDK内部及驱动开销另测，绝不把理论块大小当完整进程内存。 |
| 请求 | 统一StringLoader进行中≤1、待发≤8、间隔≥5.1秒 | 目录／区概要／二进制包共用额度；不继续使用旧的独立图片通道。 |
| 项目 Udon 开销 | 稳态每帧 p95 ≤2 ms，内容绑定每帧目标 ≤4 ms | 编辑器 Profiler 与实机行为共同观察；API不可直接量测时说明测量方法，不编造精度。 |
| 参考性能 | 低复杂度测试头像下，桌面 1080p 目标60 FPS；PCVR目标72Hz、p95帧时间≤13.9ms | G0记录CPU/GPU/头显/分辨率；超过硬件能力调整参考配置并说明，不向所有访客保证。 |
| 测试持续时间 | 60 分钟循环访问／返回 | 热身后多轮相同路径，纹理数与受控队列回到预算，无持续上升；总进程内存另作趋势记录。 |
| 正常加载体验 | 在带宽≥20Mbps、RTT≤200ms且无错误条件下，目录＋首区文字目标≤15秒，选中详情图片目标≤15秒 | 从真实请求计时，记入排队和解码；故障／旧缓存不承诺此时限，只要求安全提示。 |
| 发布站点预算 | 两数据站各≤544.008MiB组包；主站≤700MiB | 固定1主站＋2数据分片，站点余量不得被未计入的旧版本占用；原始源图与Git历史另列报告。 |

本路线没有图片像素版本标记。若BC1画质不合格，先记录透明背景、量化和尺寸的影响，再在生产上传前修改分组或编码方案；不能伪称2MiB固定块就保证所有素材好看。

## 4. 必测场景编号

| 测试 | 方法和通过条件 |
| --- | --- |
| T-01 工具链恢复 | 在干净目录恢复包并编译场景；记录精确版本，没有依赖作者机器的绝对路径或 SDK 本体提交。 |
| T-02 字节与节流 | 实际客户端从Pages直链读取含0及非UTF-8字节的.bin，ResultBytes与产物一致；只读取一次该属性，全部请求共享节流，失败有限退避，目录复核合并。 |
| T-03 原子包版本 | 同路径交替旧／新包，混合目录／区概要修订，检查错组、截断和坏头均拒绝；新目录使变动区正文／详情立即失效，后续失败不恢复；未变区可复用。不依赖图片读回。 |
| T-04 复用回调 | A 墓碑请求中切到 B，再返回 A，迟到图片不得覆盖 B；归还外壳不会保留上一个人名／头像。 |
| T-05 空间一致 | 两名访客各自到同一墓位看到同版本内容；查看详情、传送和刷新不改变其他人界面。 |
| T-06 四区与导航 | 全部区有可达入口，边界／四区交界／复活不抖动加载；未加载与无内容状态可区分。 |
| T-07 全量与长时 | 三档数据逐区访问，满档检查577地址、512组、4,096槽；60分钟加载／Destroy循环，2缓存＋1暂存纹理与队列有界，记录原生上传单帧耗时。 |
| T-08 内容显示 | 九类、三玩家、无玩家、七逻辑图片、纯文本、缺字、长故事、桌面与PCVR坐姿全部可读且不越界。 |
| T-09 状态清理 | 各非公开状态从当前部署及受控旧路径排除，扫描合图和预览；新鲜请求确认已更新，另记录CDN／客户端旧缓存持续时间，不承诺即时消失。客户端获知新修订后不再显示旧内容；隐藏／撤下后的恢复必须重新审核。清理失败不能报告成功。 |
| T-10 发布失败 | 一个图片站失败、目录新旧不一、Actions重试；不报告全成功、不重复扣次、无错图，明确失败范围。 |
| T-11 账本一致 | 同一初始发放／奖励重放不增余额；余额1并发接纳两条最多成功1条；同条目三名相关玩家不产生三份额度；改名／解绑／恢复不重领。撤销已用奖励不删墓碑也不漏记差额。 |
| T-12 身份与授权 | 冒认、重复绑定、过期挑战、非VR对象和代建未授权分别处理；不收集凭据，不把未核验显示为认证。 |
| T-13 分享闭环 | 浏览器无登录／无VR身份可读；页面进入GitHub投稿／评审指南；不按点击或邀请发奖，没有项目访客追踪。 |
| T-14 恢复接续 | 从备份重建静态产物与工程；镜像不重复发奖；独立 Fork 使用新社区身份，保留原条目来源，同号条目不误合并，余额不自动回流原社区。撤下记录在恢复后仍生效，世界发布权单独确认。 |
| T-15 安全贡献 | 恶意PR无法获取发布凭据／执行特权脚本；危险图片或HTML被拒绝或安全转义，不把用户输入当命令。 |
| T-16 舒适性与设备 | 戴头显检查字体距离、控制器指向、不同身高、坐姿、音量和特效；桌面键鼠路径独立通过。 |
| T-17 普通成员维护 | 用无仓库写权限成员完成新建、普通修改、换图、举报、撤下与恢复申请；候选修订待审时原批准版本不变，举报不会由投稿者直接变更正式状态，关联玩家不能自动取得编辑／发布权；处理记录可追溯。 |
| T-18 评审公平与申诉 | 对质量相当的赞成／修改／拒绝意见使用相同奖励标准；补充评论不重复计奖，自审／利益冲突不能自行确认，独立复核者处理申诉并记录原因。任务不足不以拉人弥补；容量耗尽停止新建消费，但已确认贡献仍记录或明确待结算，不静默拒付。 |
| T-19 BC1显示 | 编译全部准确重载，加载角标／人像／含字合图，确认DDS头已剥离、尺寸／格式／mip正确、颜色方向与七图裁切正确；Windows桌面和PCVR均测，不能仅凭注册表通过。 |
| T-20 新手投稿到达 | 不熟悉Git的用户不用JSON／Fork完成表单、拖图、补充信息，区分两种回执；发布后按短码确认标题并到达，验证错码、空槽、旧版本和错世界均有指引。 |

## 6. 发布检查清单

- [ ] G0～G4 全部满足，所有已确认必需项有证据，无未处理高风险图文错配或隐私暴露。
- [ ] 维护者确认真实世界归属、上传资格、素材许可与内容警告；先私有验收，公开发布另行授权。
- [ ] 世界内没有生产写入凭据、真实私密证据或完整不可撤下的离线墓碑备份。
- [ ] 生产地址表、布局版本、协议版本、内容快照和分享页链接对应，测试配置不能混入生产。
- [ ] Pages 各站直链检查、大小报告和发布结果齐全；失败不能自动开放新分享入口。
- [ ] 备份可恢复，至少明确可接续的维护者／组织权限，恢复后不会复活已撤下内容。
- [ ] 额度政策已公布且批准，真实奖励没有使用仍待决定的候选比例。
- [ ] 停服、数据源故障、容量不足和紧急撤下都有可执行操作步骤。

## 7. 日常运行与事故处理

建议每次内容发布由 Actions 生成体积、引用、状态与清理报告；维护者定期查看构建失败、待审积压和站点预算。可以使用 GitHub 托管的定时工作流，但定时并非实时保证，不是必须常驻的个人服务。本次不创建任何定时任务。

错误发布优先停用相关公开内容、修复并发布安全快照；不能盲目还原整站历史，因为历史可能包含后来被撤下的人物内容。奖励消费记录与网站部署恢复分开，不因网站回滚再次发放初始次数。

若主维护者失联：由授权继任者恢复仓库、核验最新有效状态、取得或重新配置发布资源，再恢复服务；没有原世界发布权时需新世界接续，不假装能够自动取得旧世界所有权。

## 8. 证据记录格式

每项结果至少记录：测试编号、时间、执行者、源提交、世界构建、内容发布号、Unity／SDK、设备与图形设置、数据规模、网络条件、步骤、实际结果、截图／录屏或日志位置、通过／失败／未执行及剩余问题。

面向公开的报告不收集无关访客身份或把他人账号写入性能日志。任何“已达到4,096容量”的描述必须能链接到对应构建与实机证据。
