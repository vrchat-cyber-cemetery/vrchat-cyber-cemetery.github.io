# VRChat 世界／Unity 详细开发计划

更新：2026-10-03。Unity任务尚未实施；SDK静态核验与离线模型验证已执行，但不是客户端验收。需求见 [requirements](../requirements/REQUIREMENTS.md)，原子图文包设计见 [RUNTIME-DATA.md](RUNTIME-DATA.md)。

## 1. 首版交付物

1. 可复现的 Unity 世界工程与依赖清单，能由接续维护者重新构建。
2. 共享墓园场景：公共入口、分区导航、稳定墓位、休息空间及投稿／举报／分享指引。
3. UdonSharp 浏览系统：静态目录、区域概要、8碑原子图文包、本地墓碑池、有界下载与缓存、定位与错误状态。
4. 编辑器工具：布局／地址表生成、配置校验、假数据与故障注入、构建前检查。
5. GitHub 发布对接：同一审核快照导出世界数据和静态分享页；绑定、评审与额度在世界外处理。
6. PC 桌面、PCVR、多访客、满容量数据与长时间运行测试记录，以及发布和紧急撤下操作手册。

“完整世界交付”不包含所有 4,096 座真实内容或全量独立美术，使用合成数据验收系统能力。真实内容必须另行获得发布依据。

## 2. 工具链与工作环境

### 2.1 固定基线

- Unity 2022.3.22f1、VRChat Worlds SDK 3.10.5 为本轮已核验的计划基线，来源见 [可行性评估](FEASIBILITY.md)。创建项目时再次复核，并保存确切解析后的依赖版本。
- 优先 Windows＋官方 Creator Companion 的 World 模板。使用 SDK 内置 UdonSharp 与 ClientSim，不额外混装旧 unitypackage。
- Built-in 3D 渲染管线；不使用 URP／HDRP，也不依赖运行时自定义原生插件。
- PC／PCVR 共用 Windows 世界构建，分别测试鼠标键盘与头显控制器，不把桌面通过视作 VR 通过。
- 当前 macOS 工作区可保存工程和进行经过验证的编辑器开发；若走官方 VPM CLI／模板恢复路线，先通过 M0，不承诺本机能替代 Windows 客户端链路。[官方模板路线](https://vcc.docs.vrchat.com/guides/using-project-template-repos/)

### 2.2 工程建议布局

以下均为未来创建的路径，本次没有建立 Unity 工程：

```text
world/  # 工作区下的独立世界仓库；工程根目录
  Assets/CyberCemetery/
    Scenes/            # BootstrapTest、Cemetery、StressTest
    Udon/              # 数据、分区、显示、图片、交互
    Editor/            # 生成、验证、测试配置；不上传执行
    Prefabs/           # 墓碑、区域入口、详情、占位
    Art/               # Mesh、Materials、Textures、Audio、Fonts
    Tests/             # 编辑器测试与固定样本
    Config/            # 布局、端点表、预算配置与生成清单
  Packages/            # 包清单、解析锁定及所需 resolver
  ProjectSettings/
```

仅 `Cemetery` 是生产发布场景；其他场景服务于调试与压力测试。运行时行为继承 UdonSharpBehaviour，编辑器工具和测试允许使用普通 Unity Editor C#，严格分开编译与引用。

提交自己的 Assets 及 `.meta`、ProjectSettings、依赖清单和 resolver；排除 Library／Temp／缓存与可恢复的 SDK 包本体。用可再分发的美术、音频和字体，记录来源许可，避免 Fork 后无法合法重建。[VPM 源码控制](https://vcc.docs.vrchat.com/vpm/source-control/)

## 3. 场景与体验结构

### 3.1 生产场景层级

```text
Cemetery
  WorldDescriptor       安全出生点、复活高度、世界配置
  Environment           地面、道路、静态遮挡、照明、音频
  EntranceHub           项目说明、分区目录、投稿与举报入口
  RegionAnchors         固定区域坐标与入口；不持有远端完整内容
  LocalGravePool        128 个原型显示外壳，按实际预算调整
  LocalUI               详情面板、加载／错误、舒适性选项
  RuntimeServices       下载、解析、分区、纹理与诊断
  EditorOnly            调试工具与开发辅助
```

环境碰撞、地面和导航路径不随着个人数据加载而消失。池中的墓碑不作为必须存在的主要通行障碍，避免访客因本地加载状态不同而发生卡位。

### 3.2 用户路径

- 出生后先看见完整安全地面、项目含义和加载提示；没有网络也不出生在空场景或悬空区域。
- 目录显示可参观区域；步行或导航到固定区域，先展示文字，再补图片。
- 靠近墓碑可阅读标题／墓志铭；交互打开自己的详情面板，看到故事、日期含义、玩家和纪念图片。
- 在世界中知道如何到静态分享入口、用墓碑 ID 定位页面、投稿或举报；不在世界里输入 GitHub token 或执行账本操作。
- 从发布回执取得 `12-34` 这样的短定位码，在出生点输入后先确认标题，再选择指路或到达安全步道；不以Display Name识别“本人”。
- 分区加载失败保留明确状态和重试入口，不把失败区域显示为“这里没有任何墓碑”。

### 3.3 美术与可访问性原则

先灰盒，后纪念氛围美术；不默认选择恐怖、跳吓、闪烁或将纪念内容游戏化的视觉设计。艺术风格细节另行确认，不阻塞技术原型。

使用一致的墓碑外壳与少量材质，不为每份投稿导入独立模型。详情阅读优先：中文／英文、长标题、换行、低对比图片、无头像、坐姿及不同身高都要测试。关闭投稿文本的富文本解析，缺字不能导致空白或崩溃；对未支持字符给出可读替代与投稿预检提示。

照明以烘焙为主，静态反射为起点，避免每座墓碑实时光源和大量全屏透明特效。移动的池对象不标记为永久静态批处理几何；遮挡由稳定环境承担，动态对象只作为被遮挡者。是否启用烘焙遮挡由场景形状和实际收益决定。[Unity 2022.3 动态对象遮挡](https://docs.unity3d.com/2022.3/Documentation/Manual/occlusion-culling-dynamic-gameobjects.html)

## 4. 阶段与工作包

人日估算假设开发者熟悉 Unity／Udon，使用基础可授权素材；是范围估计，不是交付日期承诺。每阶段都要产出证据，不能只勾选任务。

### M0：环境、基线与可复现工程（1～2 人日）

前置：指定开发／测试机器和维护者，不要求先决定奖励比例。

- [ ] M0-01 记录 Unity、SDK、包解析版本、OS、Windows 测试机、头显和控制器；确认官方版本，不随意升级。
- [ ] M0-02 由官方 World 模板建立未来工程路径，设置序列化／可见 meta 文件与包恢复方式，做清洁目录恢复测试。
- [ ] M0-03 添加 VRC Scene Descriptor、安全出生点、地面、复活高度和 SDK 层／碰撞矩阵，解决构建错误。
- [ ] M0-04 在 Windows 执行空场景 Build & Test，分别验证桌面与 PCVR 基本进入、移动和退出；ClientSim 仅作本地辅助手段。
- [ ] M0-05 登记真实 Pages 组织／仓库和测试资源 URL；不在计划里预造域名，不把 GitHub 页面链接当图片直链。

产物：可重复导入的空世界、工具链清单、环境验收记录。出口：G0。维护者登录和世界发布仍由其本人控制。

### M1：最高风险原型（5～8 人日）

前置：M0 可运行；仅使用合成文本和无人物隐私测试图。

- [ ] M1-00 按协议v1建立固定样本，复用已通过的离线模型边界用例；不是将Node模型直接移植为生产Udon解析器。
- [ ] M1-01 生成577个固定VRCUrl和4,096墓位映射，测量编译／序列化／客户端初始化；不再比较A/B或数千图片版本槽。
- [ ] M1-02 编译SDK证据列出的准确重载，从真实Pages读取含零字节／非UTF-8的.bin；ResultBytes只读取一次，验证原始字节保真与统一StringLoader节流。
- [ ] M1-03 锁定DirectXTex texconv版本／校验值，在GitHub托管Windows环境生成BC1 DDS并正确提取单mip块，用角标／人像／含字图验证方向、背景、色彩；比较4／8碑一包成本，在生产上传前冻结或提交有依据调整。
- [ ] M1-04 验证原子包旧修订、错组、截断、区域期望变化和迟到回调全部拒绝；不进行像素版本标记或GPU回读研究。
- [ ] M1-05 两区128外壳、2缓存图集＋1暂存；测试LoadRawTextureData、Apply(false,true)、Destroy生命周期与30分钟切换，分别测CPU／GPU及SDK内部开销。
- [ ] M1-06 汇总POC-01／02／04／05：字节→版本检查→BC1显示链路可复现，有限重试无增长；失败定位为格式、SDK或平台问题，不声称已运行成功。

产物：最小 Udon 实验场景、下载与缓存报告、地址表报告。出口：G1；图片一致性未过时只允许继续文字灰盒，不开展完整图片版 Beta。

### M2：共享墓园灰盒与固定空间（6～9 人日）

前置：M1 核心寻址可行。

- [ ] M2-01 建立入口、道路、区域入口和休息点；先完成两个相邻区域，再扩成全容量锚点布局。
- [ ] M2-02 编写编辑器布局生成器，分离墓碑 ID／墓位／资源槽位，生成可重复布局校验和版本；不手工摆放 4,096 个完整 Prefab。
- [ ] M2-03 完成本地 RegionController 和有界池，测试四区交界、回头、快速传送、复活与暂停恢复。
- [ ] M2-04 建立全区导航，访客可以到达每个有内容的固定分区，空区与加载失败明确区分。
- [ ] M2-05 用两名真实客户端访问相同／不同分区，验证同版本同墓位以及个人详情互不干扰；不由 Master 代替所有人下载。
- [ ] M2-06 维护静态环境碰撞与池对象交互分离，检查不同加载状态下仍可正常走动。

产物：可共同参观的灰盒墓园、稳定坐标映射、多人录屏。出口：G2 的空间部分。

### M3：文字、图片和浏览交互（4～6 人日）

前置：M2、M1 图片门槛。

- [ ] M3-01 完成九类对象、可选日期含义、标签／链接、0～3 名玩家、缺图／缺玩家的视图绑定。
- [ ] M3-02 完成本地详情面板：开关、翻阅故事／纪念图、加载状态、返回；按键与控制器指向分别验收。
- [ ] M3-03 完成统一内容队列、原子图文包验证、逻辑图块、缓存与自建纹理Destroy；无图包不分配纹理，不沿用ImageDownloader的Dispose。
- [ ] M3-04 加入分帧数据绑定，不在一个 Update 中遍历所有墓位；缓存组件引用，诊断操作不得成为帧率瓶颈。
- [ ] M3-05 字体授权与 CJK 覆盖、长文本溢出、坐姿／身高、视觉对比、光敏与音量测试；提供本地低特效设置。
- [ ] M3-06 完成投稿／举报／分享指引，显示 ID 和分区，不假定世界内任意链接打开或剪贴板权限已存在。
- [ ] M3-07 加入错误与诊断面板；新目录使活动区失效时立即清除旧正文和详情，新数据失败仍保持占位；提示不泄露完整请求正文或私密信息。
- [ ] M3-08 完成短定位码输入、范围校验、目标标题确认、本地指路／安全传送及发布版本提示；错误码、空槽、撤下、错世界和旧数据有可读说明。

产物：100 条合成混合内容的完整浏览切片。出口：AC-01、AC-06、AC-10 的对应子项与 G2。

### M4：GitHub 数据与静态发布对接（4～6 人日）

前置：M1 接口可行；可与 M2／M3 部分并行。

- [ ] M4-01 实现源／运行时 Schema 和内容生成器，冻结协议 v1、布局版本、索引范围、文本与图片预算；区分公开内容与治理记录。
- [ ] M4-02 实现固定8碑图集布局、BC1离线编码、原子包头和JSON、网页JPEG衍生；校验尺寸、单mip、块长度与授权，不在图中编码版本标记。
- [ ] M4-03 同配置生成577地址和满容量1主站＋2数据站产物；每数据站256包且≤约544.008MiB，主站独立限额；生产上传前预置真实站点。
- [ ] M4-04 分离不可信投稿校验和受信任发布工作流，锁定操作权限及依赖版本，禁止在特权流程执行投稿脚本。
- [ ] M4-05 实现所有状态过滤与资源清理，特别覆盖旧合图、旧预览和曾保留的版本路径。
- [ ] M4-06 跨站发布前预检、就绪检查、最后激活根目录；部分失败不回传“全量发布成功”，重试不重复结算。
- [ ] M4-07 生成各站体积／流量估算／引用完整性报告，完成备份恢复与错误回滚演练。

产物：可复现的公开内容导出与静态发布流程。出口：G3 中构建和清理部分。

### M5：静态分享与社区循环（5～8 人日）

前置：M4；技术上可并行，不等于政策已批准。

- [ ] M5-01 每墓碑生成稳定静态分享页，直接输出完整 HTML 标题与预览信息，无 JavaScript 也可阅读；默认使用无人物身份的项目通用预览。
- [ ] M5-02 完成阅读→投稿指南→GitHub Issue／PR→审核→发布的路径，支持为他人／非 VRChat 对象建立墓碑。
- [ ] M5-03 生成邀请文案、复制链接的浏览器端增强及评审入口；不构建短链服务，不按点击或邀请人数发奖。
- [ ] M5-04 按已批准pilot-v1用模拟记录演练评审和创建额度；实现与独立核验通过后才启用真实账本。
- [ ] M5-05 身份与控制权核验走 POC-06；绑定可选已确认，基础GitHub成员流程不依赖VRChat登录，已核验标记必须有真实依据。
- [ ] M5-06 检验重复事件、并发消费、任务取消、奖励撤销、独立申诉、无评审任务及容量耗尽；补齐无写权限用户的修改／换图／举报／撤下和利益回避，额度不等于墓位预订。
- [ ] M5-07 分享页与世界同步下架，稳定链接改为通用不可用页，清理预览产物；告知第三方缓存边界。
- [ ] M5-08 用GitHub Issue Form接受无需JSON／Fork的投稿，区分投稿回执与发布回执；发布成功后在原Issue更新分享页、墓碑ID、定位码、世界入口和发布序号，按新手旅程实测。

产物：无个人运营服务器的传播与贡献闭环，详见 [COMMUNITY-LOOP.md](COMMUNITY-LOOP.md)。出口：G4，未确认政策时仅封闭模拟。

### M6：全容量、优化与验收（4～7 人日）

前置：M3、M4，公开闭环验收还需 M5。

- [ ] M6-01 生成100／1,024／4,096三档数据，满档512包、28,672张逻辑图映射；检查2数据站和主站的硬预算，不以共享少量测试图片假装全容量。
- [ ] M6-02 按测试矩阵验证 2 名真实访客，另做 8 名受控访客观察；记录头像负载，不把他人高复杂度头像计入本世界独立性能保证。
- [ ] M6-03 60 分钟跨区／详情切换／回访压力测试，测纹理峰值、队列、GC、Udon帧开销与客户端错误。
- [ ] M6-04 烘焙灯光、LOD／材质复用、透明覆盖、文字 Canvas 更新与遮挡优化；逐项 A/B 测量，不一次加入多种无法归因的优化。
- [ ] M6-05 真实 Windows 桌面与 PCVR 记录稳定帧时间、中文阅读和输入，异常网络／旧缓存／撤下组合测试。
- [ ] M6-06 回填证据与预算，超标则收敛池、视距、美术或合图方案；影响已确认能力时提交需求变更，不隐瞒降级。

产物：全容量报告、性能与可靠性证据、可公开的限制说明。出口：G3、G4 的完整验证。

### M7：发布、交接与运行手册（2～3 人日）

前置：G0～G4 通过，维护者明确授权发布。

- [ ] M7-01 SDK 构建面板无阻断错误，检查出生／复活、世界信息、内容提示、版权和分享页链接。
- [ ] M7-02 先私有上传并邀请测试，确认最终世界 ID 与发布归属；测试与生产配置严格分离。
- [ ] M7-03 记录 world build、内容发布号、Unity／SDK版本与来源提交，验证发布后 URL 不重定向、数据和图片均可下载。
- [ ] M7-04 完成日常内容发布、失败重试、紧急撤下、镜像恢复、维护者离职与凭据轮换手册；不在 Git 中放登录凭据。
- [ ] M7-05 将完整需求AC-01～AC-24证据交付维护者，含新用户投稿到定位旅程；明确未完成的真实客户端测试，再决定公开发布。

上传需要符合平台的账号资格和世界权限；登录及公开发布是实施阶段的维护者操作，不由本次计划自动执行。[首个世界与测试说明](https://creators.vrchat.com/worlds/creating-your-first-world/)

## 5. 人力、依赖与估算

上述阶段合计约 **31～49 人日**，建议预留约 30% 风险缓冲，即约 **40～64 人日**。不含从零学习 Unity／Udon、大量原创场景美术、取得设备、人物授权等待和平台审批等待；不是承诺数周内必定上线。

建议责任分工：

- Unity／Udon：环境、世界、浏览、运行时与性能。
- 数据／GitHub：源校验、图片衍生、静态发布、分享和账本。
- 内容治理：授权、评审质量、核验、申诉和政策。
- 测试维护者：Windows／PCVR、第二客户端、发布与恢复证据。

一个人可以承担多个技术角色，但不能在奖励流程中独自核验自己的利益相关贡献。多人开发可并行 M2／M3 与 M4／M5，不能绕过共同接口和门槛。

## 6. 退出标准

文档和编辑器能运行都不算完成产品。只有共享世界、静态内容更新、分享循环、已批准治理政策、全部目标客户端验收和维护交接均完成，才能称为完整首版。单纯浏览原型可以提前交付，但必须标明不含真实奖励或未验证图片更新，不冒称目标全部达成。
