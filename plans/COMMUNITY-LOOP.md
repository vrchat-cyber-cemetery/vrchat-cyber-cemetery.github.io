# GitHub 驱动的社区正向循环

更新：2026-10-03。用户已确认优先依赖GitHub，不依赖个人运营的长期服务器；不另设后台数据库、登录或短链服务。新手操作与世界定位见 [SUBMISSION-JOURNEY.md](SUBMISSION-JOURNEY.md)。

## 1. 价值循环与贡献循环

核心不是让人不断“消费墓位”，而是让纪念被认真保存、他人能阅读、社区有人愿意把关。

这些机制用于促进正向循环，不保证仅靠分享或奖励就一定获得持续参与；需用封闭试点的评审质量、积压、申诉和维护成本验证，并允许调整或暂停激励。

```text
有人想纪念自己／他人／一段经历
              ↓
      GitHub 投稿＋授权声明
              ↓
       独立评审与自动校验 ←──── 成员查看真实待审任务
              ↓                         ↓
       审核接纳并结算额度        有效贡献获确认与去重
              ↓                         ↓
    Actions 发布世界数据＋分享页  按确认政策获得更多创建机会
              ↓                         │
    可阅读、可分享、可在世界参观 ────────┘
              ↓
       邀请他人阅读或开始纪念
```

“邀请他人”不是未经请求批量发送消息，不自动创建墓碑，也不代替对可识别人物的同意。用户自行分享已公开的稳定链接。

## 2. 不同人的参与路径

| 人群 | 能做什么 | 不应要求什么 |
| --- | --- | --- |
| 普通网页访客 | 阅读分享页、了解项目、查看投稿与评审指引。 | 不强制登录 GitHub／VRChat，不先领额度才能阅读。 |
| VRChat 访客 | 在共享墓园浏览全部已发布内容，查看对应 ID／网页入口。 | 不靠绑定账号才能参观，也不因自己没投稿只看到空墓园。 |
| 投稿成员 | 为本人、他人、非 VRChat 人物或非人物对象提交纪念。 | 不要求被纪念对象有 VRChat 账号；不自动假设其已去世。 |
| 评审成员 | 对真实待审任务提出有依据的意见。 | 不要求有剩余创建额度才可以评审，不要求投赞成票才有奖励。 |
| 内容相关人 | 报告错误、请求隐藏或撤下、提出申诉。 | 不要求其先公开私密证明，也不要求其先参加评审换额度。 |

GitHub 原生投稿和评审通常需要 GitHub 账号；这是明确的参与门槛，不声称匿名网页写入已实现。若未来要求无 GitHub 账号也能直接提交，需要另行选择托管入口或人工代录政策，不能偷偷加入个人服务器。浏览和阅读不受此门槛影响。

成员VRChat绑定已确认可选，额度主体为GitHub数字ID。无论选择哪种成员资格规则，被纪念对象无需 VRChat 账号都必须满足。

## 3. 各环节如何不依赖个人服务器

| 环节 | GitHub 原生方案 | 权限和边界 |
| --- | --- | --- |
| 阅读与分享 | Pages 静态 HTML、CSS、图片和少量可选浏览器脚本。 | 不在浏览器请求带写权限的 API；JS 关闭仍可读内容。 |
| 投稿 | Issue 表单，或 PR 提交内容与图片；维护者可将 Issue 整理为候选变更。 | 先告知公共性；未审附件不直接成为世界图片源。 |
| 内容预检 | Actions 读取不可信投稿，校验结构和安全图片格式。 | 不向投稿代码暴露生产凭据，不任意执行投稿脚本。 |
| 人工评审 | GitHub 中结构化意见、修订、处理记录和利益回避。 | 平台行为是提交来源，质量认定仍由授权社区成员负责。 |
| 接纳与记账 | 受保护主数据中的唯一操作及额度事件，Actions／授权维护流程串行核验。 | 接纳内容与消费共同记录，部署重试不重复记账。 |
| 静态发布 | Actions 从批准快照构建并发布 Pages 和必要图片分片。 | 发布成功才返回分享链接；部分失败保持明确状态。 |
| 邀请 | 用户复制稳定链接／通用邀请文案，页面提供“创建纪念”和“参与评审”入口。 | 不发送自动外部消息，不搭建点击追踪或短链服务。 |
| 数据接续 | Git 仓库、规则、资源清单与授权资料备份。 | 镜像沿用原状态；Fork 身份及额度互认按 DEC-06。 |

Pages 提供静态托管，不能把它当作运行服务器端表单逻辑的环境；浏览器辅助只能生成草稿或导航到 GitHub，不能偷偷保存写入令牌。[GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

默认面向普通用户的是Issue表单，不要求JSON或Fork；PR保留给高级贡献者。收到投稿先返回Issue回执，审核与实际部署全部成功后再给发布回执：分享页、墓碑ID、发布序号、固定世界入口和定位码。世界读批准数据、按短码导航，不靠GitHub登录或玩家显示名找“本人”。

## 4. 分享页设计与生命周期

### 4.1 页面最小信息结构

1. 项目名称、墓碑标题、“这里埋葬了什么”、墓志铭与故事。
2. 经批准的图片、日期含义、标签与 0～3 名相关玩家；空字段自然省略，不虚构身份。
3. “在 VRChat 墓园参观”的项目入口及区域／墓位 ID。真实世界发布前显示未上线说明，不编造世界链接。
4. “分享这份纪念”“创建一份纪念”“参与社区评审”“报告问题／请求撤下”。
5. 内容更新时间、状态说明、公开传播与外部缓存告知。

URL 使用稳定的 `entries/<entry-id>/`；不强制依靠单页应用运行 JavaScript 才得到正文。HTML 在构建时转义投稿文本，外部链接采用安全协议白名单，拒绝脚本 URL；不接受投稿自定义 HTML／JS。

默认社交预览使用项目通用图和通用介绍，不把人物头像、名字、敏感故事直接铺到聊天卡片。为人物内容生成专属预览需要单独明确传播同意政策，且纳入撤下清单。

### 4.2 状态统一

| 状态 | 分享页处理 |
| --- | --- |
| 草稿／`pending` | 不产生含私人投稿内容的公开分享页，GitHub 审核入口不是批准的传播页。 |
| `published` 且部署成功 | 页面可分享，与世界使用相同批准快照；分享可在没有 VRChat 账号的浏览器中阅读。 |
| `disputed`／`hidden`／`removed` | 保留稳定链接的通用不可用提示，不保留原正文、人物身份、图片或专属预览。 |
| 构建／部署失败 | 不通知“已完成分享”；仅在旧版本当前仍允许公开时才可保留，否则应改为通用不可用提示。清理部署也失败时，明确记录尚有受控残留并启动紧急处理，不宣称已经撤下。 |

分享页部署与世界数据可能不同时完成；以同一发布清单协调，不能在图片站点失败时宣布整批内容已上线。内部源文件状态与外部可访问状态分别记录。

撤下清理包括 HTML、独立图、缩略图、合图、预览图和受控历史产物。外部聊天软件已缓存的预览、搜索缓存、截图与 Fork 不保证召回，应在投稿前告知。

## 5. 奖励设计：奖励贡献，不奖励声量

### 5.1 建议保留的核心规则

- 每GitHub社区成员初始一次新建墓碑机会，数字ID去重，VRChat绑定可选。
- 额外次数来自去重且独立核验的有效评审，而不是邀请、阅读量、点赞、赞成率或评论条数。
- 支持、要求修正、建议拒绝均可能是有效贡献；不能因坚持授权或隐私规则而失去奖励。
- 同一评审任务的修订与补充不重复计奖；自审、利益冲突、已知多账号串谋进入复核。
- 有额度仍需内容审核，也需有可用墓位和资源预算，不构成永久发布权。
- 奖励不可购买、转让或提现，不引入交易市场。

pilot-v1已批准3次有效评审换1次、每投稿最多2获奖任务，独立维护者确认。不要在页面上预先承诺“邀请几个人就送一块墓地”。

### 5.2 冷启动与供给平衡

- 用少量获得授权的示范内容解释九类纪念，不用虚构人物死亡或爬取他人故事填满墓园。
- 维护者先承担基础审核，开放真实待审任务与评审清单，给新成员可模仿的高质量示例。
- 第一批成员可以使用初始额度；没有评审任务时明确显示暂无任务，不鼓励制造垃圾投稿赚次数。
- 先做小规模封闭试点，观察评审耗时、积压、修改率和申诉，再确认兑换比。3:1已选为试点值，不是已证明最优，后续政策变更需明确版本。
- 采用可选、经同意的贡献致谢，而非排行榜竞争；不以人物悲伤程度或故事传播量排序。
- 当容量耗尽时，停止新内容接纳和创建消费并说明原因，不先扣次再找空间；已发布内容仍可阅读。
- 已确认的有效评审仍需记录并按政策结算，不能因满园而抹去贡献。确需暂停兑换时公开原因与恢复条件，保留待结算事件；暂停新的评审任务与处理已完成贡献分别决定。维护者缺席时请求也不能因工作流未运行而被遗忘。

## 6. 不建追踪服务器的观测方法

从 GitHub 已存在的投稿、评审和合并记录生成周期性静态摘要即可：

- 合法投稿数、首次投稿成员数、有效评审数、待审时间分布。
- 修改后通过率、撤下与申诉数量、维护者处理时间。
- 各站发布体积、构建失败次数、额度更正与异常重复请求数量。

这些数据用于健康检查，不可据此宣称测出了“分享点击转化率”。默认不收集邀请关系、浏览器指纹或阅读事件。GitHub／第三方平台自身的安全日志仍存在，“项目不做追踪”不等于平台完全不记录访问。[Pages 数据收集说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

## 7. 闭环验收

用合成内容完成两条路径：

- **传播路径**：无 VRChat 账号的访客打开分享页 → 阅读 → 查看为他人纪念的规则 → 通过 GitHub 提交 → 获审并发布 → 获得自己的分享链接。
- **贡献路径**：成员查看真实任务 → 给出有依据的评审 → 独立确认 → 按已确认政策得额外创建机会 → 新投稿再次经过审核。

同时测试分享后撤下、代建未授权被拒、无账号阅读、没有待审任务、重复领奖和没有空墓位。全部路径不依赖私人服务器，不在任何客户端保存发布凭据。
