# 从投稿到在VRChat找到墓碑：最简用户旅程

日期：2026-10-03。面向不会Git、Unity或JSON的用户；这是待实现的流程设计，不代表仓库已经开放投稿。

## 1. 用户只需理解四步

1. **填写纪念内容**：从分享页或世界入口打开投稿指南，进入GitHub表单。
2. **等待审核并补充信息**：在原Issue查看进度、回答问题，不重复提交。
3. **收到发布回执**：拿到分享页、墓碑ID、定位码和世界入口。
4. **进入墓园并定位**：在入口输入定位码，确认标题，选择指路或前往。

不要求写JSON、Fork、创建PR、运行脚本、安装Unity或在VRChat里填长表单。浏览分享页不需登录；提交仍需GitHub账号。这个门槛在“开始投稿”前明说，不伪装成匿名后端。

## 2. 入口设计

### 2.1 世界入口

设置固定“创建／查找纪念”区域，分为：

- 创建墓碑：固定网站地址、预烘焙二维码、简短四步说明。
- 查找墓碑：定位码输入框、已发布数据版本、加载状态。
- 了解／求助：投稿要求、为什么需要审核、举报／撤下方式。

二维码和文字地址都指向同一个Pages指南，手机扫描与桌面手动访问都可用。不依赖Udon打开系统浏览器或写入系统剪贴板，也不要求在头显中输入GitHub凭据。

### 2.2 分享页入口

每页提供“我也想留下一份纪念”“参与社区评审”“在VRChat参观”“报告问题”。创建入口先说明：可以纪念自己、他人或非人物对象；被纪念对象不必是VRChat玩家；为他人建碑仍需遵守同意与图片授权。

初版不额外构建一套自建登录或复杂投稿SPA。GitHub表单与Pages指南足以完成闭环；若试用表明填表理解成本高，再增加纯浏览器本地预览，但不能把前端变成保存写凭据的代理。

## 3. 最少必填表单

| 项目 | 用户填写方式 | 说明 |
| --- | --- | --- |
| 这里埋葬了什么 | 短文字 | 可是人物、关系、记忆等；不预设死亡事实。 |
| 对象类型 | 九类下拉选择 | 每类用中文说明。 |
| 公开与授权声明 | 明确的确认项 | 已知会公开；有权使用图片；涉及可识别他人时满足同意要求。勾选不替代人工审核。 |

可选项：自定义标题、墓志铭、故事、日期及其含义、标签、相关链接、0～3名玩家、主图／纪念图／头像。不填标题时由“这里埋葬了什么”生成可编辑的建议标题，正式记录仍有必填title。玩家账号引用和绑定不自动出现在必填核心字段中；已确认不作为领取额度前提；提交前展示GitHub成员身份和pilot-v1说明。

图片在普通textarea附件区域拖放或粘贴，文字标注“主图”“纪念图1”“玩家1头像”；不让用户生成图集。模板保留说明示例，附件区不设置会阻止正常附件编辑的代码块用途。GitHub官方表单支持textarea与文件附件。[表单语法](https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/syntax-for-githubs-form-schema)

首次提交允许纯文字，后续在同一Issue补图。不得要求身份证件、Cookie、令牌或私密聊天记录直接贴进公共Issue。公开前就要告知Issue本身是公开的，而不是等内容通过后才告知。

## 4. 世界与GitHub如何交互

```text
VRChat入口／分享页
       ↓ 固定指南链接
GitHub Issue表单 → Actions结构校验 → 社区人工评审
       ↓ 投稿回执／需补充说明             ↓
       └────────────── 原Issue持续更新 ───┤
                                         ↓
                           批准快照＋额度／墓位校验
                                         ↓
                  Actions构建：网页＋区域概要＋原子图文包
                                         ↓
                        Pages就绪检查 → 发布回执
                                         ↓
               VRChat读取目录／区域／组包 → 输入定位码参观
```

世界不向GitHub写入、不自动登录、不判断访客GitHub身份。用户通过GitHub完成写入，Actions处理；世界通过固定的允许列表地址只读批准数据。

Actions解析Issue中的结构化内容，给出可读错误与修正位置；不要求用户读构建日志。只下载受控来源的附件，限制域名／重定向／大小／类型，拒绝任意URL抓取，转码后重新编码生成产物。未审附件不能成为Udon直接下载源。

需要转PR时由维护流程生成草稿，普通用户只需回复Issue。解析和处理程序来自受信任默认分支，用户输入不作为shell命令或工作流代码。只有批准后才分配正式ID／墓位和结算额度；部署重试不重复扣次。

## 5. 两种回执，不能混淆

### 5.1 投稿回执

Issue编号就是投稿凭据。回执说明当前阶段、下一步、如何修改和如何接收GitHub通知。不得此时给出虚假的正式墓位或宣称世界已经可见。

建议进度状态：已收到 → 需要补充／待评审 → 已批准待发布 → 发布失败待重试／已发布。内容状态与部署状态分开；Issue被关闭不自动等于已在世界出现。

### 5.2 发布回执

只有该条目所需的根目录、区域、组包和分享页均部署检查成功后才发送。发布回执至少包含：

- 墓碑ID，例如 `CC-000123`。
- 墓碑标题和批准的内容版本，方便确认不是其他条目。
- 定位码，例如 `12-34`，以及“第12区／第34槽”的文字解释。
- 稳定分享链接。
- 已核实的VRChat世界页面入口；实际世界未发布前不编造链接。
- 本次发布序号、完成时间；提示客户端或CDN可能仍在同步。
- 明确操作：“进入世界 → 出生点查找终端 → 输入12-34 → 确认标题 → 指路／前往”。

回执保存在原Issue的固定机器人评论并更新，不为同一次发布重复刷屏。网站也显示相同定位码和版本，使用户不必翻找长评论历史。

## 6. 定位码与世界导航

首版采用5字符的两段式显示 `12-34`（两段各2位，加一个连接符），展示第12区第34槽，范围均为01～64；内部减1得到区域11、槽位33。输入允许去除空格，并规范化为两段数字；不接受URL、任意脚本或世界外坐标。

流程：

1. 本地检查格式／范围，错误直接说明例子，不产生下载。
2. 确认当前社区和布局配置，按已预置地址加载对应区域。
3. 验证目标槽当前有 `published` 内容，显示墓碑ID、标题和数据版本。
4. 用户确认后可显示本地指路标记，或将本地玩家带到该墓位附近的固定安全步道；不移动其他访客，不传送进墓碑碰撞体。
5. 同时按需请求该组图文包；图片未完成时仍可阅读区域文字并看见加载状态。

安全传送只调用本地玩家的TeleportTo，目标来自预设步道锚点，不使用投稿提供的任意坐标；坐在禁止传送的Station时提示先离开座位，不强行绕过。传送由用户确认触发，不在网络反序列化回调中直接执行。[VRChat玩家位置](https://creators.vrchat.com/worlds/udon/players/player-positions/)

定位码公开，不是权限令牌。不能通过Display Name自动识别“我的墓碑”，用户为他人建立或改昵称都不影响查找。

固定墓位不自动复用；若未来允许复用，需要带墓碑ID校验的新定位规则，不能让旧分享链接无提示地带到别人的墓碑。不同Fork的同码属于不同世界，页面必须标明社区和目标世界。

## 7. 找不到时的明确指引

| 情况 | 用户看到什么 | 系统处理 |
| --- | --- | --- |
| 仍待审核 | 尚未发布，请在Issue查看进度 | 不承诺出现时间，不引导反复提交。 |
| 已批准未部署 | 正在发布，还没有可用发布回执 | 保留原Issue状态，失败说明重试。 |
| 回执版本比世界新 | 数据正在同步，显示当前／目标发布序号 | 提供节流刷新；不谎称即时刷新一定绕过CDN。 |
| 码格式或范围错 | 示例与允许范围 | 不发网络请求。 |
| 目标无公开内容 | 该位置暂无可公开浏览的墓碑 | 不泄露被撤下内容的标题或原因。 |
| 网络／包版本不匹配 | 文字或占位、加载状态和重试提示 | 不展示错误组或已知过期内容。 |
| 进入了另一个世界／Fork | 请核对回执中的社区与世界入口 | 不在多个社区之间猜测个人身份。 |

不承诺从网页链接自动把玩家送到世界内的墓位：世界入口与墓位导航是两个动作，短定位码是它们之间明确可靠的信息交接。

## 8. 新用户验收

邀请未用过Git和Unity的测试者按指南完成：纯文字投稿、拖放图片、补充审核信息、找到发布回执、分享、进入世界、输入码并到达目标。记录理解错误和步骤耗时，不将“熟悉项目的开发者能完成”当作易用性通过。

同时测试非VRChat纪念对象、代他人建碑、无VRChat绑定访客、错误码、尚未发布、旧目录、已撤下与跨Fork同码。没有自建后台，没有客户端写凭据，也不要求用户手工维护JSON。
