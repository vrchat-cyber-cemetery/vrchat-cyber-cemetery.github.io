# 投稿试点运行手册

## 当前可用流程

网站填写／预览 → GitHub Issue表单和附件 → Actions校验／固定回执 → 维护者审核 → 源内容与初始额度共同提交 → Pages网页发布 → 分享链接和预留定位码。

采用same_repository模式，只使用本仓库GITHUB_TOKEN完成事件处理、源码变更和显式发布触发。App自动PR及跨仓库BC1发布留待后续阶段；兼容模式无需额外登录服务或常驻服务器。

## 维护者操作

先核验表达、人物同意、图片权限和利益关系。回执的折叠区给出当前投稿完整SHA-256：

- 回复 /publish 加64位投稿修订，接纳该版本；修改后旧修订失效。
- 回复 /hide CC-000001 暂时隐藏。
- 回复 /dispute CC-000001 暂停争议内容。
- 回复 /remove CC-000001 正式撤下。
- 回复 /restore CC-000001 重新审核后恢复。

只接受config/policy.json中数字ID对应的维护者。不能审核自己的投稿，恢复自己创建的内容也需独立维护者。改名不重新领取，重复发布不重复消费。

正文和规范化图片进入公开Git源码，网页只导出published内容。隐藏／撤下后重建页面和素材，源历史及外部副本不保证召回。成员、账本和源码目录不复制到Pages产物。

## 发布与重试

接纳和部署分开。部署失败可以重跑Publish website，或重复原publish指令；不会再扣一次。不要还原含已撤下内容的历史站点。

发布记录确切源SHA，回执使用同一快照；原Issue后来修改时，说明新修改仍待审核。

## 当前限制

- VRChat世界未上传，定位码是未来位置预留，不报告世界已可参观。
- 自动评审兑换未开启；初始1次与接纳消费已实现，政策仍为3:1。
- App未注册，目前没有自动生成投稿PR或跨仓库发布。
- 网页选图只本地预览，图片需在GitHub附件区上传；规范化背景和缩放说明见参与指南。

## 检查与开发

运行npm run check、npm run build:site；npm run preview仅本地临时检查，不是生产服务。
